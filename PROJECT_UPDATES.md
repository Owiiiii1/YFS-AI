# Описание обновлений проекта

Этот файл содержит историю функциональных изменений проекта. Новые записи добавляются сверху внутри соответствующей даты.

## 29 августа 2026

### Ручное создание заявки: каталоги, стафф, вес и двойная цена

- Форма ручной заявки пересобрана по смысловым блокам: клиент, событие, размер и цена, торт, логистика, референс, примечания и оплата.
- Добавлен виртуальный клиент Staff: уникальная запись, скрытая из списка клиентов. Чекбокс «Стафф» рядом с выбором клиента отключает выбор обычного клиента и привязывает заявку к Staff.
- Повод выбирается из каталога; пункт «Новый» открывает поле ввода, и новый повод сохраняется в каталог. Каталог заполнен из текущих заявок и типичных поводов пекарни.
- Вкус выбирается из фиксированного каталога тортов; пункт «Кастом» открывает текстовое поле и не пополняет каталог.
- Аллергии работают как поводы: каталог из заявок и диалогов, пункт «Прочее» добавляет и сохраняет новое значение.
- Перед количеством гостей — переключатель расчёта по гостям или по весу. Неактивное поле только для чтения; вес считается по таблице гостей.
- Итоговая цена разделена на расчётную и ручную. При заполнении размера оба поля получают расчёт; сохраняется ручная цена.
- В референсе осталось текстовое поле и добавлена загрузка фото.
- Поле примечаний доступно при ручном заполнении. Сводка бота показывается только у заявок, которые создал бот.

Проверка: миграция каталогов и Staff применена; расчёт 15 гостей / 6 lb совпадает с таблицей; фронтенд собран в staging и атомарно опубликован.

- Создан единый файл описания функциональных обновлений проекта.
- Добавлено постоянное правило проекта: после каждого реализованного изменения обновлять этот файл до завершения задачи.
- Записи содержат назначение, итоговое поведение и выполненную проверку без секретов и персональных данных.

Проверка: файл истории и постоянное правило проекта созданы и доступны в рабочем каталоге.

### Настройки бота: автовключение после ручного режима

- В разделе «Управление ботом» добавлена кнопка «Настройки бота».
- Добавлен параметр времени автовключения бота после простоя в днях. Значение по умолчанию — 3 дня.
- Когда оператор явно переводит отдельный диалог в ручной режим, система запоминает момент переключения.
- Если после последней активности в диалоге прошло заданное количество дней, бот автоматически включается обратно.
- Проверка выполняется фоновым планировщиком каждый час.
- Автовключение не отправляет сообщение самостоятельно: бот ожидает следующее входящее сообщение клиента.
- Закрытые диалоги и диалоги без зафиксированного ручного переключения не затрагиваются.

Проверка: сценарий с просроченным ручным режимом включает бота; свежая активность оставляет ручной режим включённым.

## 28 августа 2026

### AI-анализатор ответов и промптов

- В «Управлении ботом» добавлен сохраняемый семишаговый мастер AI-анализа.
- Анализатор получает вопрос администратора, выбранный Instagram/Facebook-диалог, переписку, технические трассировки и активный `prompt_config`.
- Для анализа используется отдельное назначение AI-модели; модель клиентского чат-бота выбирается независимо.
- В каждой карточке OpenAI, Anthropic и Gemini можно отдельно назначить модель для ролей «Чат-бот» и «AI-анализ».
- Подключёнными могут оставаться несколько API-ключей, но для каждой роли активна только одна модель. Переключение требует подтверждения.
- Анализатор показывает наблюдаемые факты, предполагаемую причину, уверенность, варианты решения и ограничения.
- После уточнения пользователя формируется объяснение предлагаемого изменения и сравнение «было/будет».
- Изменения не применяются на этапе анализа или preview. Применение возможно только после отдельного подтверждения.
- Разрешены только известные пути `sections`, `templates` и `business_values`; неизвестные операции отклоняются.
- Чувствительные изменения цен, адресов, депозита, Zelle и весовой сетки выделяются предупреждением.
- Активный промпт обновляется атомарно с проверкой ревизии и сохранением предыдущей версии.
- Сессии и этапы анализа сохраняются в отдельной истории; незавершённую сессию можно продолжить после закрытия окна.
- Добавлены кнопка завершения сессии и заметная анимация во время работы AI.
- Добавлены `bot_decision_traces` и `ai_runs` для фиксации источника ответа, пути решений, модели, времени выполнения и ошибок без сохранения API-ключей и бинарных файлов.
- Техническая телеметрия автоматически очищается через 90 дней.

Проверка: Gemini structured output, безопасный patch preview, защита от конфликтов ревизий, prompt parity, EN/RU/UK smoke-сценарии и production-трассировка.

## Правило ведения файла

После каждого изменения проекта необходимо добавить краткую запись с датой, назначением изменения, затронутым поведением и выполненной проверкой. Секреты, API-ключи и персональные данные в этот файл не добавляются.
