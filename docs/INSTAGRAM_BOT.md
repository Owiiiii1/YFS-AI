# Instagram-бот Young Fashion Show

Дата фиксации: 2026-09-03  
Канал: только Instagram Direct  
Источник знаний: `docs/prompt.txt`  
Операционные URL и Meta: `docs/INSTAGRAM_ASSISTANT.md`

Этот файл — запись всех продуктовых решений по Instagram-боту. Если правило здесь расходится со старым текстом в `prompt.txt`, действует этот документ.

Глобальный тумблер бота (`bot_settings.bot_enabled`) после внедрения **выключен**. Включать вручную в Bot Management, когда канал готов.

---

## 1. Что бот делает

Официальный Instagram Direct-ассистент Young Fashion Show.

- Отвечает на вопросы бесконечно. Диалог технически не заканчивается.
- Отправляет только официальные ссылки на формы. Анкеты внутри Direct и внутри админки запрещены.
- Принимает конкретные обращения и передаёт их менеджеру.
- Если человека нашли в основной базе JFS по email — клиенту это не рассказывает подробно; полная карточка уходит только оператору.
- Если ответить нельзя — спрашивает, нужен ли живой оператор. Выключается только после «да».

Бот не продаёт в Direct, не называет цены, не обещает карьеру / контракт / агентство, не выдумывает даты и статусы заявок.

## 3. Два режима диалога

Диалог никогда не закрывается технически. Меняется только режим.

### Вопросы

Информационные вопросы: что такое YFS, возраст, опыт, мальчики, города, как проходит шоу, ссылки на сайт / Instagram / YouTube.

- Отвечать можно бесконечно.
- Журнал «Ответы бота» и Telegram **не** создаются.
- После формы или передачи менеджера человек может снова задавать вопросы — это снова режим вопросов.

### Кейс

Конкретная ситуация: хочет подать заявку, уже подавал, жалоба, бренд / дизайнер, стафф, «переключите на человека».

Бот:

1. Выслушивает.
2. Отправляет ссылку на форму и/или принимает обращение для менеджера.
3. Возвращается к вопросам, если человек продолжает спрашивать.
4. Может снова стать кейсом.

## 4. Анкеты только ссылками

Встроенные анкеты удалены: шаблоны в Bot Management, таблицы `questionnaire_templates` / `questionnaire_submissions`, пошаговый сбор в Direct.

Список ссылок, которые бот отправляет, правится в Bot Management → **Ссылки на анкеты**. Это таблица в `business_values.form_links`. Бот шлёт URL из этой таблицы, не из `docs/prompt.txt`.

Страница `/questionnaires` осталась по тому же URL, но называется **«Ответы бота»** и показывает закрытые кейсы (`bot_replies`), не заполненные анкеты.

Официальные формы:

| Кто | Ссылка |
| --- | --- |
| Родитель / участник | https://form.youngfashionshow.com/crm_form_ppigu/ |
| Команда / партнёр (визаж, фото, видео, стилист, бэкстейдж, спонсор) | https://form.youngfashionshow.com/crm_form_e5l3g/ |

Дизайнер / бренд: форму участника не подсовывать как основную. Собрать суть обращения и передать менеджеру.

В Direct нельзя собирать длинную анкету (имя ребёнка, рост, опыт, город по полям). Если человек готов участвовать — ссылка на форму.

## 5. Что можно и нельзя говорить клиенту

### Всегда

- Заявку / обращение приняли. Передаём менеджеру / команде.
- Если нужна форма — дать ссылку выше.
- Язык ответа = язык клиента (en / ru / uk; испанский и армянский — если модель может).
- Коротко: 1–3 абзаца, один CTA, один вопрос за раз.

### Никогда

- «Мы нашли / не нашли вашу заявку».
- «Вас нет в базе».
- «Я отправил это в Telegram».
- Точная цена, депозит, скидка, рассрочка.
- Контракт, агентство, скаутинг, оплачиваемая работа, карьера модели.
- Выдуманные даты, площадки, статусы.
- Служебные флаги JFS: Bitrix, импорт, парковка, питание, репетиции как операционные тумблеры.

Если человек говорит, что уже подавал заявку: принять это как факт и передать менеджеру. Не проверять и не комментировать наличие формы на сайте.

## 6. JFS: только чтение

Подключение: `JFS_DB_*` в `/var/www/yfs-ai/.env` (копия `DB_*` из JFS). Laravel-коннект `jfs`. Записи запрещены.

### События

Бот может рассказать всё из публичных полей события.

Читаем `events` + `event_infos`:

- название, город, площадка, даты начала / конца
- описание из `description_i18n` (en → ru → uk → es, HTML снимается)

Не отдаём в промпт операционные поля: парковка, питание, Bitrix, импорт, цены билетов как внутренние тумблеры.

Подгружаются только если человек спрашивает про ивенты / города / даты.

### Поиск клиента

Ключ поиска — **только email**. В JFS email уникален на `app_users`. Телефон не использовать как ключ поиска.

Если email неоднозначный или битый — не выдумывать. Предложить оператора / менеджера.

Дизайнеров и стафф в JFS **не ищем**. Только форма или передача менеджеру.

Дети: `children` по `client_app_user_id` (имя, дата рождения). Это только для оператора, не для текста клиенту.

### Если нашли в JFS

Клиенту: «мы вас нашли, информацию передали». Без детей, телефона, роли, внутренних полей.

Оператору (Telegram + «Ответы бота»): полная карточка + дети + вопрос.

### Если не нашли в JFS

Клиенту всё равно: обращение принято, менеджер свяжется. **Не** говорить, что человека нет в базе.

Оператору: не найден + email + вопрос.

## 7. Оператор

Два разных сценария. Их нельзя смешивать.

### Человек сам просит живого оператора / менеджера

Бот сразу:

1. Пишет, что подключает оператора (`human_handoff`).
2. Выключает бота в этом диалоге (`bot_enabled = false`).
3. Ставит статус `pending_human`.
4. Пишет в Telegram-канал, что пользователю требуется оператор.
5. Создаёт запись типа `operator_needed` в «Ответах бота».

### Бот не способен ответить

Бот **не** выключается сам. Сначала спрашивает, нужен ли оператор (`operator_offer`).

- «Да» → тот же handoff, что выше.
- «Нет» → остаётся в режиме вопросов.
- Пока ответа нет — ждёт, бот включён.

Тема ожидания: `bot_awaiting_topic = operator_offer`.

Оператор в админке может снова включить бота в диалоге. Планировщик `bot:reenable-after-manual-inactivity` может включить бота после тишины, но сам клиенту не пишет.

## 8. Что падает в Telegram и в «Ответы бота»

Один Telegram-чат из Settings: канал, группа или ветка внутри группы с темами. Вопросы без кейса туда не идут.

| Тип | Когда |
| --- | --- |
| `form_sent` | Бот отправил ссылку `form.youngfashionshow.com` |
| `manager_request` | Жалоба или «уже подавал» / поиск без найденного email-кейса |
| `operator_needed` | Нужен живой оператор |
| `client_found` | Email найден в JFS, обращение передано |
| `client_not_found` | Email искали, в JFS нет; клиенту сказали «приняли» |

В канале: тип, Instagram-пользователь, номер диалога, краткое резюме, email / карточка JFS / вопрос — если есть.

Админка: `/questionnaires` → «Ответы бота». Ссылка открывает Instagram-диалог.

## 9. Промпт: ядро + темы по нужде

Полный `docs/prompt.txt` в каждый ход не кладётся.

### Всегда (`always_include`)

| id | Зачем |
| --- | --- |
| `role_brand` | Роль, бренд, сайт, Instagram, YouTube, телефон |
| `prohibited` | Запреты |
| `tone_language` | Тон и язык |
| `routing` | Вопросы vs кейс, формы, оператор |
| `operator` | Как спрашивать / не врать про перевод |

### По сигналу диалога

| Сигнал | Тема |
| --- | --- |
| Ивент, город, дата, площадка | `events` + LIVE EVENT FACTS из JFS |
| Родитель, участие, цена, возраст, опыт | `parents` |
| Визаж, фото, видео, стилист, партнёр | `team_partners` |
| Дизайнер, бренд | `designers` |
| «Уже подавал», email, «никто не позвонил» | `client_lookup` + CLIENT LOOKUP FACTS |
| Жалоба, возврат, фото/оплата | `complaints` |
| «Развод», агентство, «подумаю» | `objections` |
| Системный follow-up | `follow_up` |

В Bot Management у темы есть чекбокс «подгружать в каждый ответ».

Сброс живого конфига на этот набор:

```bash
php artisan bot:prompts:reset-yfs
```

Перед заменой делается snapshot текущих промптов.

## 12. Что сознательно не делаем

- Не пишем в JFS и Bitrix.
- Не ищем клиента по телефону.
- Не показываем клиенту факт «есть / нет в базе».
- Не обсуждаем внутренние анкеты CRM как будто бот их видит.
- Не грузим весь `prompt.txt` в каждый запрос.
- Не оставляем Facebook живым продуктом.
- Не включаем глобальный бот автоматически после выкладки промпта.
